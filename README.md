# Bounded-Capacity Weighted Petri Net Reachability Backend

A Rust/Axum backend that decides **marking reachability for an ordinary
weighted place/transition Petri net with an explicit finite capacity on every
place**. It returns a concrete firing path to every reachable target, emits
P-invariant candidates and re-verifies every piece of evidence independently
before sending it.

> **Scope (read this before using the result).** Reachability here is decided
> by exhaustive search inside the finite product of per-place capacities.
> That decision is exact **for the bounded model you declared**. It is **not**
> a complete reachability decision for an *unbounded* Petri net: deleting a
> capacity admits markings outside the box and can change the answer. Every
> response carries this statement explicitly
> (`scope.equivalent_to_unbounded_reachability_decision = false`), and the
> input language intentionally has no "unbounded place" option, so a bounded
> answer can never be mistaken for an unbounded one.

## Behavioural contract

1. **Enabling checks all input arcs together; firing is atomic.** A
   transition is enabled only if *every* input arc's weight is available; a
   firing then consumes all inputs and produces all outputs as one step
   (`crates/pn-core/src/fire.rs`).
2. **Capacity overflow forbids the firing; tokens are never truncated.** If
   the produced marking would exceed a place capacity, `fire` returns
   `CAPACITY_OVERFLOW` with the would-be count and no successor marking. It
   does **not** clamp the count to the capacity.
3. **Reachable targets come with a path; P-invariant candidates are
   validated.** Each reachable target returns a shortest BFS witness, which is
   replayed step-by-step by the independent `pn-verify` crate. P-invariants
   are generated by a Farkas row algorithm and re-derived from the arcs before
   they are reported.
4. **The bounded/unbounded distinction is explicit everywhere** (input
   language, `/version`, every response body, and the test suite).

## Project layout

```
crates/
  pn-core/       solving kernel: typed model, atomic firing, bounded BFS
  pn-lang/       input language: petri-analysis/v1 JSON + classified errors
  pn-solver/     analysis orchestration, incidence matrix, Farkas invariants
  pn-verify/     independent evidence verification (witness/invariant/deadlock)
  pn-fixtures/   synthetic nets + independent reference oracles
  pn-server/     Axum HTTP backend, configuration, run identity, logging
  pn-tests/      independent integration + end-to-end HTTP tests
config/          server configuration file
examples/        ready-to-POST request bodies (3 standard nets + 1 invalid)
scripts/         reproducible build/test/run demo
```

The separation is real, not cosmetic: the server depends on the solver, the
solver on the kernel and input language, and the verifier/fixtures sit beside
them with no dependency on the solver's search code. There is no single-file
implementation, no call-only shell, and no fixed return value.

## Build, test and run from a clean directory

```bash
# from the repository root
cargo build --release                       # build the server
cargo test --workspace                      # all tests (59 on the verified run)
cargo clippy --workspace --all-targets      # lint (clean with -D warnings)

# one-command reproduction (build + tests + clippy + boots server + curl):
./scripts/run_demo.sh
```

Run the server:

```bash
# defaults to 127.0.0.1:8080; config file optional
cargo run -p pn-server
# or
PN_HTTP_BIND=127.0.0.1:9000 PN_LOG_LEVEL=debug ./target/debug/pn-server
```

Configuration layers, lowest to highest priority: built-in defaults →
`config/server.conf` (path overridable via `PN_CONFIG_FILE`) → environment
variables (`PN_HTTP_BIND`, `PN_MAX_STATES_CEILING`, `PN_LOG_LEVEL`).

## HTTP API

`POST /api/v1/analyze` with a JSON body. Optional header `X-Run-Id` pins a
correlation id (safe charset only; otherwise one is generated); the same id
is echoed in the response and every related log line.

```bash
curl -sS localhost:8080/api/v1/analyze \
  -H 'content-type: application/json' \
  -H 'x-run-id: demo-mutex-0001' \
  --data-binary @examples/request-mutex.json
```

Other endpoints: `GET /health` → `{"status":"up"}`; `GET /version` reports the
schema, server version and `unbounded_reachability_complete: false`.

### Request language `petri-analysis/v1`

| Field | Meaning |
|---|---|
| `schema` | Must be exactly `"petri-analysis/v1"`. |
| `places[]` | `{name, capacity}`; `capacity` is a **required finite** u64. |
| `transitions[]` | `{name, inputs[], outputs[]}`; arcs are `{place, weight>0}`. |
| `initial` | Positional token vector in places-declaration order; must fit capacities. |
| `targets[]` | `{label?, marking?}` or `{label?, by_place{name: count}}`. |
| `options` | `{max_states?, compute_invariants?, find_deadlocks?}`. |

### Response and verdicts

Each target returns `verdict` ∈ `REACHABLE` (with a verified `path`),
`UNREACHABLE` (the finite box was fully exhausted), or `INCONCLUSIVE`
(the configured state budget was hit — **never** silently reported as
unreachable). The response also lists reachable `deadlocks`, each
independently re-checked (`deadlocks_truncated:true` warns when enumeration
hit the state budget and the list is partial), and per-target P-invariant
necessary-condition results (`necessary_condition_holds=false` is a sound
unreachability certificate; equality is necessary but not sufficient).
`invariant_generation_truncated` is reported honestly if the generator row
budget is exhausted.

### Errors are classified, not collapsed into success

* Malformed body → HTTP **400**, category `SYNTAX`.
* Wrong shape/missing field/bad schema version → HTTP **400**, category
  `SCHEMA`, with a location pointer.
* Well-formed but invalid model (unknown place, zero weight, initial or
  target over capacity, …) → HTTP **422**, category `SEMANTIC`.

Unknown/exceptional conditions therefore cannot be returned as a successful
reachability verdict.

## Standard nets used for verification

* **Mutex** (`examples/request-mutex.json`): `idle ↔ busy`, one resource
  token. Held state reachable in one `acquire`; `(idle,busy)=(1,1)` is inside
  the box but unreachable (P-invariant `idle+busy=1`).
* **Bounded producer/consumer** (`examples/request-producer-consumer.json`):
  buffer 2. Concrete 9-marking reachable set; the capacity-saturated marking
  `(free,ready,done)=(0,2,2)` is the unique deadlock (produce lacks a free
  slot; consume would overflow `done` to 3).
* **Linear deadlock net** (`examples/request-deadlock.json`): a unique
  terminal marking `(0,0,1)` reached in exactly two firings.

## How independence of the reference answers is guaranteed

`pn-tests` never asks the kernel "is your answer still your answer". Expected
results are (a) hand-derived for each small net, and (b) cross-checked against
two structurally different enumerators in `pn-fixtures`, one of which
(`oracle::indie`) **re-implements the firing semantics from scratch without
calling any kernel firing routine**. Evidence (witness paths, invariants,
deadlocks) is re-derived by `pn-verify`. See [TESTING.md](TESTING.md) for the
full list of concrete assertions and the recorded verification run.
