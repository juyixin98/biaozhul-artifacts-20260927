# hcomp — canonical-Huffman compression backend

A from-scratch, deterministic **canonical Huffman** codec with a block-directory
container (`HCMP`), a filesystem object store and an Axum verification API.
Rust only, no external services: all inputs and peers are local fixtures.

The headline constraints (see [`FORMAT.md`](FORMAT.md) for the normative text):

* **Equal-frequency tie-break is fixed**: tree construction pops a min-queue
  keyed on `(weight, tree height, minimum leaf symbol)` — equal weights merge
  the shallower tree first, then the one holding the smaller symbol — so code
  lengths are a pure deterministic function of the input and an independent
  implementation reproduces them exactly.
* **Canonical codes**: only `(symbol, length)` pairs are stored; code words are
  re-derived by the standard counter-and-shift recurrence, MSB-first.
* **Empty and single-symbol inputs have their own encodings** (0-symbol table;
  reserved zero-length lone symbol expanded by count).
* Decoding validates the **length set (Kraft equality), bitstream termination
  and original length**, with no over-read and no unbounded output, and checks
  three CRC layers.
* An **unknown container version is explicitly rejected**.

## Layout

```
src/
  huffman.rs    tree construction + tie-break + canonical code derivation
  canonical.rs  wire code-length table (RLE) + decoder lookup table
  bits.rs       MSB-first bit writer/reader, zero-padding verification
  block.rs      per-block encode/decode kernel
  container.rs  global header, block directory, offsets, CRCs, version
  crc32.rs      IEEE CRC-32 (compile-time table)
  error.rs      stable error taxonomy (categories are the API/test contract)
  store.rs      filesystem object store (atomic writes, id validation)
  config.rs     TOML + HCOMP_* env configuration
  api.rs        Axum routes
  runid.rs      per-request correlation id
  main.rs       hcompd server binary
tests/
  golden.rs                 three-way golden-vector tests
  property.rs               fixed-seed roundtrips + adversarial sweeps
  support/independent_decoder.rs  a second, independent Rust decoder
  support/testlog.rs        structured, run-id-correlated test logging
  golden/generate_fixtures.py     independent Python oracle + vectors
FORMAT.md     full wire-format specification
```

This is a layered implementation (data format → kernel → persistence →
verification API), not a single file or a fixed-return stub.

## Build and test from a clean checkout

```bash
# 1. compile (debug and release)
cargo build
cargo build --release

# 2. unit tests (kernels, container, store, in-process API)
cargo test --lib

# 3. (optional) regenerate independent golden vectors with the Python oracle
python3 tests/golden/generate_fixtures.py tests/golden

# 4. integration tests: golden three-way checks + property/adversarial tests
cargo test --test golden --test property

# 5. everything
cargo test
```

Expected result on the verified environment: **64 unit + 6 golden + 5 property
tests pass**, `cargo clippy --all-targets` is warning-free. Test decisions are
also appended as JSONL to `target/hcomp-test-logs/<run_id>.jsonl` (and printed
to stderr with `-- --nocapture`); each line carries a `run_id`, the
crate/format version, the concrete input and the verdict/evidence.

### Why the golden tests are independent

Golden vectors are produced by `tests/golden/generate_fixtures.py`, a
**separate Python implementation** of the whole spec (own heap, own canonical
recurrence, own RLE and container writer, own decoder). They are then checked
by `tests/support/independent_decoder.rs`, a **second Rust decoder that shares
no code with the crate**, against the real encoder/decoder in all directions:

```
Python oracle  <-->  hcomp encoder/decoder  <-->  independent Rust decoder
```

The ground-truth originals ship as `*.orig.bin` sidecars written by the oracle,
so expected answers are never generated by the implementation under test.

Golden cases include, with concrete asserted values and exact failure
categories:

* exact code-length/code tables for the tie-break profiles
  `(1,1,1,2)`, four equal symbols, `(45,13,12,16,9,5)` and a height-before-
  symbol case;
* roundtrips of the empty input, lone-symbol inputs, **all 256 byte values**,
  an **extreme-skew** 20 KB input and **fixed-seed random** 12 KB data;
* an **over-subscribed** code tree, a **truncated code word** and **bad padding
  bits**, plus an **unknown version** container.

## Configuration

Copy `hcomp.example.toml`:

```bash
cp hcomp.example.toml hcomp.toml
cargo run --release -- --config hcomp.toml
```

| setting        | default          | env override          |
|----------------|------------------|-----------------------|
| store_dir      | `./data`         | `HCOMP_STORE_DIR`     |
| max_block_len  | `1048576` (1 MiB)| `HCOMP_MAX_BLOCK_LEN` |
| max_body_len   | `16777216` (16 MiB) | `HCOMP_MAX_BODY_LEN` |
| bind_addr      | `127.0.0.1:8787` | `HCOMP_BIND_ADDR`     |
| log_format     | `plain`          | `HCOMP_LOG_FORMAT`    |

`RUST_LOG` controls tracing verbosity (e.g. `RUST_LOG=debug`).

## HTTP API

Every response carries an `x-run-id` header (you may also send your own
`x-run-id`); logs are keyed by it. Errors return
`{"ok": false, "error": "<stable category>", "detail": "..."}` with an
appropriate 4xx status — malformed input is a `422`, never a false success.

| method | path                         | meaning                                    |
|--------|------------------------------|--------------------------------------------|
| GET    | `/healthz`                   | liveness                                   |
| POST   | `/api/v1/encode`             | body → HCMP container (`application/vnd.hcomp`) |
| POST   | `/api/v1/decode`             | HCMP container → original bytes            |
| POST   | `/api/v1/verify`             | fully validate, return directory metadata  |
| PUT    | `/api/v1/objects`            | store; id from `x-object-id` header (201)  |
| POST   | `/api/v1/objects`            | list objects                               |
| GET    | `/api/v1/objects/:id`        | fetch and decode one object                |
| PUT    | `/api/v1/objects/:id`        | create-or-replace (200)                    |
| DELETE | `/api/v1/objects/:id`        | delete                                     |
| GET    | `/api/v1/objects/:id/meta`   | stat + directory metadata                  |
| POST   | `/api/v1/objects/:id/verify` | verify a stored object                     |

### Request samples

```bash
# start
cargo run --release -- --config hcomp.toml

# stateless round-trip on the command line
printf 'canonical huffman demo data aaaaa bbbbb' > /tmp/in.txt
curl -sS -X POST localhost:8787/api/v1/encode \
     --data-binary @/tmp/in.txt -o /tmp/in.hcmp
curl -sS -X POST localhost:8787/api/v1/verify --data-binary @/tmp/in.hcmp
curl -sS -X POST localhost:8787/api/v1/decode --data-binary @/tmp/in.hcmp \
     -o /tmp/out.txt
cmp /tmp/in.txt /tmp/out.txt && echo ROUNDTRIP_OK

# object store lifecycle
curl -sS -X PUT localhost:8787/api/v1/objects \
     -H 'x-object-id: demo' --data-binary @/tmp/in.txt
curl -sS -X POST localhost:8787/api/v1/objects/demo/verify
curl -sS localhost:8787/api/v1/objects/demo -o /tmp/out2.txt
cmp /tmp/in.txt /tmp/out2.txt && echo OBJECT_OK

# an unknown version is rejected, with the exact category
python3 - <<'PY'
import urllib.request
b = bytearray(open('/tmp/in.hcmp','rb').read()); b[4] = 99
req = urllib.request.Request("http://localhost:8787/api/v1/decode", data=bytes(b),
                             method="POST")
try:
    urllib.request.urlopen(req)
except urllib.error.HTTPError as e:
    print(e.code, e.read().decode())
PY
```

## Safety properties enforced on decode

* magic/version/flags gate everything else; unknown version → `unknown_version`;
* directory CRC, unique ids, contiguous in-bounds offsets, no trailing bytes;
* per-block payload-at-rest CRC and decoded-original CRC;
* code-length table: exact span coverage, reserved opcodes rejected, lengths in
  range, Kraft equality (rejects over-subscribed **and** incomplete trees);
* bitstream: exact body length, every code completed, zero padding bits,
  output bounded by `original_len`;
* filesystem ids are validated (`[A-Za-z0-9._-]`, no traversal/separators) and
  writes are atomic (temp file + rename).
