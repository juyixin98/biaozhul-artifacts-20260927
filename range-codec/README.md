# range-codec

Fixed-precision **range encoder/decoder** in Rust with:

* an integer-only 32-bit coding kernel (normalisation, explicit carry
  propagation, 4-byte tail convergence, big-endian output);
* **static frequency tables** (validated bounds; zero-frequency symbols
  cannot be coded) and an **adaptive model** with a deterministic integer
  halving rescale;
* a chunked, checksummed container format **`RC01`** with declared length and
  resource budgets;
* a filesystem persistence adapter (atomic writes, re-validation on load);
* an **Axum** HTTP verification API that states, per request, why input was
  *accepted*, *rejected* or is *indeterminate*, with a request/record id,
  key state and payload redaction;
* an **independent Python reference implementation** that generates the
  golden test vectors — the Rust answers are not generated by the Rust
  codec.

See **[`FORMAT.md`](./FORMAT.md)** for the normative integer specification.

## Layout

```
src/
  error.rs        error taxonomy: stable codes + accepted/rejected/indeterminate
  model.rs        FrequencyTable, StaticModel, AdaptiveModel (integer rescale)
  range.rs        RangeEncoder / RangeDecoder kernel + step traces
  crc.rs          CRC-32/ISO-HDLC (zlib-compatible), no external dep
  container.rs    RC01 framing, budgets, CRC, length checks
  persist.rs      filesystem artifact store (tmp-file + rename atomic write)
  diagnostics.rs  request ids, fingerprints, redacted payload logging
  config.rs       TOML + env configuration
  api.rs          Axum router (verify / encode / artifacts)
  main.rs         CLI: serve | encode | decode | verify
tests/
  golden.rs       asserts exact bytes + per-step intervals vs the oracle
  api.rs          end-to-end HTTP tests
  oracle/oracle.py independent Python kernel + container + golden generator
fixtures/
  golden/golden.json  committed vectors from the Python oracle
  raw/*.bin           synthetic samples (repeat / alternating / all / short / empty)
config/range-codec.toml
```

## Requirements

* Rust (edition 2021; developed on 1.98)
* Python 3.10+ only if you want to regenerate the golden vectors / cross-decode

## First-time run

```bash
cargo build
cargo test                       # all unit + integration tests
```

Generate the golden vectors (optional — a committed copy is already in the
repo) and run the tests that consume them:

```bash
python3 tests/oracle/oracle.py
cargo test --test golden
```

### CLI

```bash
# encode (static uniform table by default; tune with --freqs)
./target/debug/range-codec encode --chunk 4096 in.bin out.rc01
# adaptive mode (compresses repeated material well)
./target/debug/range-codec encode --adaptive in.bin out.rc01
# custom static table for a 3-symbol alphabet
./target/debug/range-codec encode --symbols 3 --freqs 2,1,3 in.bin out.rc01
# decode back
./target/debug/range-codec decode out.rc01 restored.bin
# validate without decoding to disk; prints the verdict JSON, exit 2 on reject
./target/debug/range-codec verify out.rc01
```

### HTTP service

```bash
./target/debug/range-codec serve --config config/range-codec.toml
# or with overrides
RANGE_CODEC_LISTEN=127.0.0.1:8080 RANGE_CODEC_DATA_DIR=./data \
  ./target/debug/range-codec serve
```

| method | path | purpose |
|--------|------|---------|
| POST | `/v1/verify` | validate+decode (`application/json` body `{"data":"<b64>"}` or raw `application/octet-stream`) |
| POST | `/v1/encode/static` | encode static chunks |
| POST | `/v1/encode/adaptive` | encode adaptive chunks |
| PUT | `/v1/artifacts/{id}` | store raw container bytes |
| GET | `/v1/artifacts/{id}` | metadata + base64 bytes |
| POST | `/v1/artifacts/{id}/decode` | decode a stored artifact |
| DELETE | `/v1/artifacts/{id}` | remove it |
| GET | `/healthz` | liveness |

Example:

```bash
curl -s -X POST localhost:8080/v1/encode/static -H 'content-type: application/json' \
  -d '{"num_symbols":3,"chunks":[{"freqs":[2,1,3],"symbols_b64":"AAIBAg=="}]}'
```

Rejections always carry a stable `error.code`, `decision` and the echoed
`request_id` (or an inbound `X-Request-Id`):

```json
{
  "request_id": "req_d769…",
  "decision": "rejected",
  "error": { "code": "TRUNCATED", "message": "truncated stream: needed at least 1 more bytes, had 0" }
}
```

## How the tests meet the contract

* **Integer normalisation & carry propagation** — `range.rs` encodes only in
  integer `low`/`range`; carry is propagated byte-by-byte over `0xFF` runs to
  a permanent sentinel. `encoder_step_intervals_match_oracle_traces` compares
  every `(cum, freq, low, range, emitted)` step to the Python oracle.
* **Zero-frequency symbols** — `ZERO_FREQUENCY_SYMBOL` on encode; the
  inverse lookup can never return a zero-width slot (`CODE_OUTSIDE_RANGE`
  otherwise). Covered by unit and golden tests.
* **Bounded totals / consistent update points** — total `<= 2^14`; adaptive
  rescale (`max(1, f/2)`) runs at the identical point for encoder and
  decoder (`adaptive_update_point_is_deterministic`).
* **Declared length & resource budgets** — budgets are enforced from header
  values before coding; length mismatch is rejected.
* **Tail & byte order** — four tail shifts; every integer big-endian; the
  format is documented in `FORMAT.md` §1.5–1.7 and pinned by exact-byte
  golden tests.
* **Failure categories** — truncation, bad magic, CRC, illegal tables,
  reserved flags all assert the exact error code; reserved flags are
  specifically `indeterminate`.
* **Independent answers** — golden bytes and traces come from
  `tests/oracle/oracle.py`, a separate implementation, and are committed
  under `fixtures/golden/`. The oracle's own decoder also cross-decodes
  Rust-produced containers (bidirectional interop).

## Real test results

```
$ cargo test
test result: ok. 40 passed; 0 failed   (src unit tests)
test result: ok. 11 passed; 0 failed   (tests/api.rs HTTP end-to-end)

```

Bidirectional cross-decoding (independent Python oracle reading
Rust-produced bytes) succeeds for static and adaptive containers over the
long-repeat, alternating, all-symbols, short and empty samples.

## Notes on the synthetic data

Everything under `fixtures/raw/` and the golden vectors are locally
generated. No production accounts, network services or real business data
are involved. Diagnostics log only a length/fingerprint descriptor for
input (and `<redacted len=…>` for the payload by default); raw bytes never
appear in logs when redaction is enabled.
