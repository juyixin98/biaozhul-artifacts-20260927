# 边界与版本语义

本文档固定实现所遵循的全部语义约定。测试按这些约定断言；改动语义必须同步改本文档。

## 1. 坐标压缩（离线预注册）

- 坐标只在**建表时**给出：`POST /v1/tables {"xs":[...],"ys":[...]}`。
- 每个维度独立处理，顺序固定为：**排序 → 去重 → 升序冻结**。
  - 例：`xs=[3,1,3,-7]` → 冻结为 `[-7,1,3]`，`duplicate_x=1`。
- 两轴是**笛卡尔积**：查询矩形选择的是“x 轴入选坐标 × y 轴入选坐标”上的格点。
- 冻结之后不可增删。需要新坐标系时**重新建表**（得到新 `table_id`）；旧表及其全部历史版本继续可查。
- 压缩下标是 0-based；Fenwick 前缀计数是 1-based（`<= bound` 的个数）。

## 2. 点更新

- `delta` 为 `i64`，**允许负值、零值**。
- `(x,y)` 必须同时在两轴的注册集合内；任一未注册 →
  `422 COORDINATE_NOT_REGISTERED`，**拒绝整批**，绝不做“就近/最近邻”插入。
- 同一批内同一点的多条增量**先聚合**再应用：
  - 批内净增量为 0（如 `+1,-1`）时提交成功，值不变；
  - 因此不会因中间顺序累加而误判溢出。
- 点的累计值必须保持在 `i64` 内；超出 → `422 POINT_OVERFLOW`（错误带 `previous` 与批净增量），**整批拒绝**，版本不前进。
- 空批（`updates: []`）→ `400 EMPTY_BATCH`。

## 3. 矩形查询（闭区间）

矩形是**闭区间** `[x_lo, x_hi] × [y_lo, y_hi]`。

- 边界映射到注册坐标用排序选择，不做 `bound ± 1` 算术（避免 `i64::MIN` 溢出）：
  - `x_end = # {已注册 x : x <= x_hi}`
  - `x_start = # {已注册 x : x <  x_lo}`（y 同理）
  - 入选压缩下标区间 `[x_start, x_end) × [y_start, y_end)`
- 边界落在注册坐标“之间”时，按上述计数自然夹取。
  - 注册 `x∈{−100,0,100}`，矩形 `x∈[−50,50]` 只选 `x=0`。
- **空矩形**（区间内没有任何已注册 x 或没有任何已注册 y）是**合法查询**：
  `200 {"sum":0,"empty":true}`。
- **倒矩形**（`x_lo > x_hi` 或 `y_lo > y_hi`）是**非法请求**：
  `400 INVERTED_RECT`。空矩形与倒矩形是两种不同结果，不互相混淆。
- 矩形和在树内以 `i128` 计算；结果离开 `i64` → `422 SUM_OVERFLOW`
  （各点值合法但总和过大的情形）。
- `version` 省略查最新；给整数查指定版本（含基线 `0`）。版本不存在 →
  `404 VERSION_NOT_FOUND`；负数 → `400 INVALID_REQUEST`。

## 4. 版本模型与原子发布

- 每个表独立维护版本链：建表即基线 **v0**（全零）；每批成功发布产生 `v(n+1)`。
- 所有历史版本的快照都保留，可随时“时间旅行”查询；新版本不修改旧快照。
- **原子性**：一批要么整体可见，要么完全不可见。实现顺序是
  读阶段（基于不可变快照纯计算+校验）→ 写锁内复核基版本 → 追加 WAL 并 `fsync`
  → 压入新快照。任何校验失败都发生在任何副作用之前，因此查询不会看到半批。
- 乐观并发（`base_version`）：
  - 省略 `base_version`：必须基于当前最新版本；
  - 显式给出且不等于当前最新 → `409 STALE_BASE_VERSION`；
  - 显式给出但版本号尚不存在 → `404 VERSION_NOT_FOUND`。
  - 这只约束“新提交基于哪个父版本”，不影响对旧版本的只读查询。

## 5. 持久化（文件系统 WAL）

- 数据目录下单个 `wal.log`，仅追加。帧：
  `magic(8) | seq(u64) | payload_len(u32) | JSON payload | crc32(u32)`，
  CRC32（IEEE）覆盖 `seq|len|payload`。
- 每次追加 `write_all + flush + fsync`；新建文件时 fsync 目录。
- 启动时全量重放并校验：魔数、长度、CRC、序号连续、JSON、版本链，且
  **用与在线相同的计算路径重算每批并比对存储的格点增量**。
  任一不符 → `500 CORRUPT_LOG`，**拒绝启动**，绝不静默按空库运行。
- 重新建表与重启后继续提交，表 id / 版本号都从 WAL 续上。

## 6. 错误分类 → HTTP 状态

| code | HTTP | 触发 |
|---|---|---|
| `BAD_JSON` | 400 | 非 JSON、类型不符、缺字段、未知字段 |
| `EMPTY_COORDINATES` | 400 | 建表时某轴坐标为空 |
| `EMPTY_BATCH` | 400 | 批更新为空 |
| `INVERTED_RECT` | 400 | 矩形下界大于上界 |
| `INVALID_REQUEST` | 400 | 表 id 非正/超范围、负版本号 |
| `COORDINATE_NOT_REGISTERED` | 422 | 更新引用未注册坐标 |
| `POINT_OVERFLOW` | 422 | 点累计值离开 i64 |
| `SUM_OVERFLOW` | 422 | 矩形和离开 i64 |
| `TABLE_NOT_FOUND` | 404 | 表 id 不存在 |
| `VERSION_NOT_FOUND` | 404 | 查询/基版本指向不存在版本 |
| `STALE_BASE_VERSION` | 409 | 显式基版本不是当前最新 |
| `PAYLOAD_TOO_LARGE` | 413 | 请求体超过 `max_body_bytes` |
| `CORRUPT_LOG` / `STORAGE_ERROR` | 500 | WAL 损坏 / 持久化 I/O 失败 |

所有错误响应都是 `200` 之外的状态码，且 body 形如
`{"ok":false,"error":{"code","message","request_id","run_id"}}`；
响应头回 `x-request-id` 与 `x-run-id`。异常/未知状态不会被统一返回成成功。

## 7. 明确不在范围内（避免误解）

- 不支持在线向既有表增删坐标（语义上是“重新建表”）。
- 不删除/回收旧版本快照。
- 单进程文件 WAL；不提供多进程并发写同一目录或网络复制。
- 点值语义为 `i64`；树内中间值 `i128` 仅用于保精度，不对外暴露 128 位点值。
