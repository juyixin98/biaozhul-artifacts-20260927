# 边界语义说明

本文件是规范，不是实现复述；测试据此手写期望。

## 1. 值域：有界 i64，而非数学整数

- 具体值域为 `i64`：`[-9223372036854775808, 9223372036854775807]`。
- `+ - *` 与一元负号是 **checked**：结果落到 i64 之外即产生 `overflow` 故障，
  具体执行在该点终止（不回绕、不饱和截断）。
  - 这对应 Rust 的 `i64::checked_add/sub/mul/neg`。
  - `-i64::MIN` 溢出；i64::MIN 的正数字面量无法书写，需要用 `0 - 9223372036854775807 - 1` 构造。
- 输入声明 `let x: [lo, hi];` 的边界必须是 i64 内常量且 `lo <= hi`。
- 数组长度是 1..=1_048_576 的 i64 常量；越界读写下标产生 `out_of_bounds { index, len }`。
- 断言失败产生独立的 `assert_failed` 类别。
- 非终止循环由具体执行燃料（`concrete_fuel`，默认 200000 语句/迭代步）截断，
  类别为 `fuel_exhausted`；这是测试参照执行器的界限，不是源语言的语义承诺。

## 2. 抽象域：无界中间值仅用于“分类”，随后必须夹取

区间端点允许 `±inf` 与任意 i128 整数，**但它们永远不会作为具体值混入状态**：

1. 迁移函数先在数学整数上算出结果区间 `M`（端点可能在 i64 之外）；
2. `clamp_to_i64` 计算 `M' = M ∩ i64-range` 并分类：
   - `inside`：`M = M'`，无溢出；
   - `partially_outside`：两者都非空——**部分**执行溢出，检查结论为
     `maybe_violated`（可能，而非必然）；
   - `entirely_outside`：`M'` 为 bottom——到达该点的每条执行都溢出，结论为
     `violated`（必然）；
3. 继续传播的值是 `M'`。完全溢出时后继状态为 bottom，因此后续语句被标记为
   `unreachable`。

关键约束：无界数只存在于“计算结果→分类”这一步，分类之后程序点状态中出现的
值区间都被限制在 i64 值域（或 bottom）。报告的结构化证据同时保留**数学结果
区间**与 i64 边界，使结论可被独立复核。

### 扩展运算约定

- `0 * (+/-inf) = 0`：扩展区间乘法在含零区间上保持可靠的过近似；
- 良构区间上不会出现 `+inf + -inf`（只有 lo..hi 同号组合，见 `Bound::add`）。

## 3. 数组下标检查的边界是 `[0, len-1]`

- 下标区间 `I` 满足 `I ⊆ [0, len-1]` ⇒ safe；
- `I ∩ [0,len-1] = ∅` ⇒ violated（每个具体下标都越界，给出 index 与 len）；
- 否则 ⇒ maybe_violated（区间含越界值，也含合法值）。
- 数组元素采用**弱更新**：`a[i] := e` 把 `e` 并入全体元素摘要。
  这是有据可查的过近似，不是错误；例如循环里依赖加宽头部算出的存储值会让
  元素摘要停在 `[0, +inf]`，即使头部后来被收窄到 `[0,10]`。需要精确逐元素
  摘要属于未实现功能（见下）。

## 4. 分支收窄

- `x < c` 把 x 收窄到 `[lo, c-1]`；`<=` 到 `[lo, c]`；`>`/`>=` 对称。
- `==` 与两侧区间求交；`!=` 只在另一侧是单点且恰为端点时精确削点。
- `&&/||/!` 按集合等式分配（`¬(a∧b) = ¬a∨¬b` 等）。
- 收窄只在比较两侧是**裸变量**时回写状态；对复合表达式不做逆变换
  （未实现功能，不是漏报：不回写只会损失精度，不破坏可靠性）。
- 两侧不可行时状态变 bottom（例如 `if x > 100` 而 `x ∈ [0,5]`，then 分支不可达）。

## 5. 循环不动点：加宽与可选收窄

对 `while c { body }`，记头状态 `X0`，一轮变换 `F(X) = X0 ⊔ ⟦body⟧(X ∩ c)`：

1. 先做 `widen_delay`（默认 1）轮普通 join；
2. 之后用标准区间加宽：下界若下降则跳到 `-inf`，上界若上升则跳到 `+inf`；
3. 得到后不动点后（有限高度必收敛），若 `enable_narrowing`，做至多
   `narrow_iters`（默认 2）遍收窄：只把无穷端点向新端点拉回，绝不扩张；
4. 报告保存 `pre_state`（循环前状态）与最终头部 `invariant`，以及每轮
   `iteration / widening / converged / narrowing_pass / fixpoint_stabilized` 轨迹。

证据验证器**不重跑**迭代，而是做归纳性检查：
`F(invariant) = pre_state ⊔ body(invariant ∩ cond) ⊆ invariant`。
篡改过的头部不变式会被该检查拒绝。

## 6. 结论的可靠性主张与覆盖范围

在上述语义下，分析器声称：

- 被标记为 `violated` 的检查点，**任何**到达它的具体执行都必然触发同类故障
  （穷举测试对每个“确定”案例逐输入验证这一点）；
- 任何具体故障，其位置上必有一个同类的 `maybe_violated` 或 `violated` 检查
  （穷举测试逐故障验证）；
- 被标记为 `safe` 的检查点在任何具体执行中都不发生同类故障
  （穷举测试反向验证）；
- 所有成功执行的具体终值 / 逐点赋值结果都包含在抽象结果中。

## 7. 未实现 / 无法执行的检查（明确单列，不计入“已通过”）

以下能力**不存在于本实现**，任何报告都不应被解读为已经检查了它们：

1. **除/模/移位/位运算**：语言无这些算符，不产生相关检查。
2. **关系型/符号域**：不跟踪变量相关性，如 `x - x` 会得到过宽区间；
   这是精度限制，结论仍可靠（偏 maybe）。
3. **强更新与逐元素数组索引**：数组是长度 + 单一元素摘要，无法证明特定下标的
   个别性质；循环中元素摘要可能因弱更新保持无穷（见 §3 的 loop_grow 例子）。
4. **复合表达式的反向收窄**（如 `x+1 < c` 直接收窄 x）：未实现。
5. **除零、有符号长度、别名/指针、过程调用/递归、整数提升以外的类型**：语言中不存在。
6. **非终止性验证**：分析器总是可终止（有 `max_iterations` 安全阀，触发时轨迹记录
   `fixpoint_iteration_cap`，且当前加宽状态仍是可靠过近似）；它**不**证明源程序终止。
   具体参照执行器靠燃料截断，燃料耗尽的输入不参与“成功执行”包含性断言。
7. **HTTP 实网端到端**：`scripts/verify.sh` 在未设置 `INTERVAL_ANALYZER_E2E=1`
   且无存活服务时会明确打印 SKIPPED；HTTP 行为由进程内服务测试覆盖。
8. **外部攻击面/鉴权/持久化**：服务仅监听给定地址、无鉴权、不落盘，定位为本地复核工具。
