# 明确简化与剩余限制

本项目是一个**本地、合成数据**的教学/审计参考实现，刻意把范围收窄到“投票
验签 + 双签/包围证据 + 简化最终性记账”。以下是已知限制，按风险相关度排列。

## 协议范围

1. **简化最终性，无分叉选择**：只接受“当前 justified → 下一连续时代”的链接
   触发 justified/finalized；非连续超级多数链接被记录但不驱动状态。真实
   Casper-FFG 的分叉选择、跨时代安全/可信性证明、动态验证者切换的问责
   （accountable safety）未实现。
2. **权重模型固定**：权重为正整数，仲裁阈值固定为严格 `>= 2/3`；没有按比例
   罚没、信标链余额、有效余额滞后（effective balance churn）等机制。
3. **时代快照需预先配置**：没有链上注册/质押交易；时代成员集合来自配置或
   存储中已写入的快照，目标时代无快照时验证者被判为 unknown。
4. **不做区块根有效性校验**：检查点根只要求是 32 字节；没有区块内容可查，
   无法验证“该根确实是某高度的区块”。

## 密码学与工程

5. 使用 **Ed25519**（成熟 `cryptography` 库），确定性签名使“同内容不同签名”
   的情形在同一密钥下不可能通过验签；真实系统可能用 BLS 聚合签名，本项目
   不做签名聚合或批量验签。
6. 证据绑定 `chain_id` 防跨链重放，但**没有额外的分叉 id / genesis 校验根
   链**；同一 chain_id 的多个独立部署之间证据 id 会相同，调用方需自行隔离。
7. SQLite 单文件、WAL；服务以单进程访问为前提（连接设置了
   `check_same_thread=False` 以适配 FastAPI 线程池），没有多写者协调或迁移
   框架（schema 版本号已保存在 `meta` 中，供未来迁移使用）。
8. 时间戳由日志格式化生成，证据本身不含挂钟时间；证据身份只依赖密码学内容。
9. HTTP 层没有鉴权/TLS/限流——只绑定本地回环用于演示，不要暴露到公网。

## 已验证、未验证

已通过 40 个测试与真实回放/HTTP 运行验证：

* 签名对链域、验证者、源/目标轮次、两根逐字段绑定；
* 相同投票重传不计违规；双签、包围（双向提交）、相等边界不包围判定精确；
* 伪造签名与真实冲突分别计数，且未验签输入无法产生证据/处罚标记；
* 权重取目标时代快照，成员轮换后旧证据仍被独立检查器判为有效；
* 独立检查器对真实证据判 valid，对改签名/改权重/删成员/错配类型/改证据体
  分别给出 `bad_signature / bad_snapshot_root / bad_domain /
  rule_mismatch / invalid_format`；
* 严格 2/3 连续轮次最终性、重复票不加权、分叉根不达成仲裁；
* 进程重启后投票、证据、链接权重与最终性游标从 SQLite 重建；
* 日志按 run_id/seq/validator 关联，拒绝原因具名，不把异常报成成功。

未做形式化证明、模糊测试、性能基准与多节点联网测试（本项目无网络参与者）。
