# 架构与 ROBDD 不变量

## 1. 表示法：补集边（complemented edges）

图中只有**一个**终节点 `T`（槽位 0，语义为“真”）。否定不是节点，而是边上的一个标记位：

- 常量“假” = 指向 `T` 的补集边；
- `edge.flip()` 是得到语义否定的**唯一**途径，不产生任何节点；
- 边的 32 位槽位编码为 `[补集位:1][节点索引:31]`（`src/core/edge.rs`）。

每个非终节点在唯一表中都以**低边无补集**的规范形态存储。`mk(var, low, high)`
是唯一的建节点入口，统一执行三条规则（`src/core/mod.rs`）：

1. **冗余消除**：`low == high` 时直接返回 `low`，不建节点；
2. **低边规范化**：若 `low` 带补集位，则翻转 `low` 与 `high`，并对最终边翻转；
3. **唯一表规约**：键 `(var, low_slot, high_slot)` 命中则复用既有节点。

由此 f 与 !f 共享同一物理子图，且“同函数 ⇒ 同一条规范边”。

## 2. 固定变量序

- 变量序在管理器构造时给定，变量在序中的下标即 `VarId`；
- 非终节点的顶变量严格沿“从根到叶”递增；
- `apply` 每一层在两侧最小顶变量上分流，`restrict` 命中被限制变量后取余因子，
  二者都只经 `mk` 产生节点，因此输出天然服从同一变量序。

## 3. apply（Shannon 递归）

`src/core/apply.rs`：对 `f op g`，取分流变量 `v = min(top(f), top(g))`，

```
f op g = mk(v, f_v=0 op g_v=0, f_v=1 op g_v=1)
```

关键点（曾经的 bug 来源，现由穷举测试守护）：当**进入边带补集标记**时，
它在分流变量上的两个余因子都必须翻转——`branches_at` 负责这一规则；
不带该变量的一侧两个分支都是它自身（补集位原样携带）。常量情形有
吸收/单位/翻转等直接化简（`single_terminal`），递归结果按
`(op, slot_a, slot_b)` 记忆化。

## 4. restrict（余因子）

`src/core/restrict.rs`：命中被限制变量的节点时选对应子边（子边补集位保留），
顶变量更小的节点正常重建，更大的子图原样返回。递归以“无补集进入边”为
记忆化单位，进入边补集在返回前统一翻转，保证同一物理节点只递归一次。

## 5. 管理器隔离

每条 `Edge` 携带进程内单调递增的 `ManagerId`：

- 内核入口（`apply`/`restrict`/`evaluate`/`add_root`）统一先 `require_owner`，
  跨管理器使用返回 `ForeignManager`；
- 后端把边编码为不透明令牌 `m<manager>-e<slot>`，解码时再次确认管理器存在，
  与内核校验互为纵深。

## 6. 垃圾回收

`src/core/gc.rs` 的 mark-sweep：

1. **标记**：从所有命名根边出发 DFS，沿 low/high（补集位不影响可达性）标记；
2. **清扫**：未标记非终节点置为失效（槽位不压缩，边索引保持稳定）；
3. 唯一表按存活节点重建，apply 记忆化缓存整体作废；
4. 之后使用失效边返回 `ReclaimedNode`（HTTP 410）。

“注册为根”是保留函数的唯一方式（`root_name` 字段或 `add_root`）。

## 7. 证据层为何独立

`src/verify.rs` 与 `tests/` 不把内核输出当标准答案：

- `Expr::eval` 是 AST 直接递归解释器；
- `equiv_exprs` 枚举身份空间全部赋值求两个表达式的值，分歧即给出见证；
- `equiv_edges` 额外返回“内核规范边是否相等”，等价接口据此交叉比对，
  任何内核/预言机分歧都降级为 `inconclusive` 而不是静默接受；
- 穷举集成测试另用真值表掩码与独立最小节点计数算法复核（见 `tests/exhaustive.rs`）。

## 8. 诊断与脱敏

- 请求标识中间件读入站 `x-request-id`（白名单字符校验），缺失时生成
  `req-<16 hex>`，并在响应头与响应体回带；
- 结论三类：`accepted`（200）/ `rejected`（4xx，请求不合法）/
  `inconclusive`（请求合法但证据不足）；
- 诊断日志是结构化 JSON，含管理器 id、节点数、映射规模等**关键状态**与原因码；
- `sensitive: true` 时表达式原文在错误文本与日志中只以 FNV-1a 指纹出现
  （`src/backend/diag.rs`），集成测试断言敏感串不会出现在任何响应字节中。
