# 核心算法与正确性证明

本文档说明 `internal/netmodel` 的区间运算与最小 CIDR 覆盖算法，并给出可复核的
正确性论证。所有地址运算都在地址**序数大整数**（big-endian 无符号整数）上进行，
地址空间大小为 `2^w`（IPv4 `w=32`，IPv6 `w=128`），**从不枚举地址**。

## 1. 固定的边界语义

- 一个前缀 `网络地址/p` 对应半开序数区间 `[start, end)`，其中
  `start = ordinal(网络地址)`，`size = 2^(w-p)`，`end = start + size`。
- 区间**同时包含网络地址（start）和定向广播地址（end-1）**。因此
  - `/31` 覆盖 2 个地址，`/32` 覆盖 1 个地址（IPv6 对应 `/127`、`/128`）；
  - 不采用“主机范围”约定（那种约定会丢弃网络/广播地址）。
- 输出与“允许集合 − 排除集合”的差集**严格集合等价**：不多一个地址，不少一个地址。

该策略在代码（`prefix.go` 的 `PrefixInterval`）、夹具头部
（`testdata/fixtures/golden_cases.json` 的 `boundary_policy`）和测试
（`TestBoundaryPolicyNetworkAndBroadcastInclusive`）三处同时固定。

## 2. 集合运算：并与差

`Union` 与 `Subtract`（`ranges.go`）操作排序后的半开区间：

- **并**：按起点排序后线性扫描；当 `next.start <= cur.end` 时合并。
  半开区间下 `next.start == cur.end` 是**相邻**（地址是离散整数，相邻之间没有
  任何遗漏地址），必须合并——这正是后面兄弟前缀可合并的精确数值条件。
- **差 `A \\ B`**：对 A 的每个区间维护游标，用 B 中与之相交的区间逐段切除，
  得到 A 中不被任何 B 区间覆盖的部分，最后再做一次并归一化。

二者都把区间**裁剪到 `[0, 2^w)`**，因此越界输入不会产出越界结果。

## 3. 区间 → 最小 CIDR 覆盖（贪心）

`Cover`（`cover.go`）对每个归一化区间从左到右：

1. 设当前游标为 `x`，区间右端为 `end`。
2. 计算可从 `x` 发出的**最长**（地址数最多的）合法前缀长度 `p`：
   - 对齐：`x` 必须是块大小 `2^(w-p)` 的整数倍，即
     `exp = w-p <= trailing_zeros(x)`（`x=0` 时对齐位数取满 `w`）；
   - 容纳：块不得越过右端，即 `2^(w-p) <= end - x`，即
     `exp <= floor(log2(end-x))`；
   - 取两者最小值 `exp = min(对齐位数, floor(log2(剩余长度)))`，`p = w-exp`。
3. 输出块 `(x, p)`，游标前进 `2^(w-p)`，直到抵达 `end`。

### 3.1 输出无重叠、无遗漏、无额外地址

- **无重叠/无遗漏**：游标从区间起点单调前进，每块恰好覆盖 `[x, x+2^exp)`，
  下一块紧接其后，直到等于 `end`。块与块首尾相接，既不相交也不留缝。
- **无额外地址**：容纳条件保证每块终点不超过 `end`；对齐条件保证块是合法
  CIDR；输入区间即目标差集，故所有地址都属于目标集合。
- 跨多个归一化区间时，区间之间本身不相邻（否则 `Union` 已合并），故不会错误
  合并分属不同连通段的地址。

### 3.2 输出块数最小（关键）

把目标集合看成完整二叉前缀树。一个长度为 `2^e`、对齐于 `2^e` 的连续地址段，
正好是树上某个深度 `w-e` 的**完整子树**，可由单个前缀表示。

**引理**：在任一目标连通段（归一化区间）的最左地址 `x` 上，任何覆盖都必须在
`x` 处放置一个包含 `x` 的前缀；该前缀不能跨越目标边界（否则引入额外地址）。
设算法选择的块大小为 `2^e`（`e` 是满足对齐与容纳的最大指数）。任何同样包含 `x`
且不越界的前缀，其块大小指数 `e' <= e`。

- 若 `e' < e`，该选择覆盖的地址是算法块的严格子集，**不可能减少**后续所需块数；
- `e` 已是合法上限，任何 `e' > e` 要么破坏对齐、要么越过右端，都会引入额外地址
  或产生非法 CIDR。

因此在最左地址上取最大合法块是一个安全的贪心选择：它不增加总块数，且把剩余
问题归约为更短的同类问题。对剩余段归纳，即得算法输出的块数最少。

### 3.3 不存在可再合并的兄弟前缀

两个等长前缀互为**兄弟**，当且仅当它们的网络序数仅在第 `w-p` 位不同；二者拼接
恰为父前缀（长度 `2^(w-(p-1))`、对齐于父边界）。

若输出中存在一对可合并兄弟，则它们覆盖一段长度为 `2 * 2^(w-p)`、父对齐的连续
地址。考察算法第一次进入这段时的最左地址：该地址既是父对齐的（至少有
`w-p+1` 个尾随零），其后的剩余长度也足以容纳父块，于是第 3 步必然直接选择更大
的父块，而不会分别发出两个兄弟——矛盾。故输出中**不存在任何可再合并的兄弟对**。
这一点由 `verify.go` 的 `findSiblingMerges` 对每次结果显式检查（翻转兄弟位）。

> 与“最小块数”的等价性：完整子树划分中，存在可合并兄弟意味着块数还能减一，
> 因此 3.2 的最小性与 3.3 的无兄弟可合并是同一结论的两种表述；两者都被独立测试。

## 4. 独立校验（不信任被测构造函数）

`VerifyCover`（`verify.go`）在每次计算后运行，且**不调用** `Subtract`/`Cover`：

1. 结构校验：前缀长度合法、块按其大小对齐、无重复、未越出地址空间；
2. 用裸 `big.Int` 重建每块区间，两两求交检测**重叠**；
3. 用独立的局部排序合并 `localNormalize` 重建覆盖集合，与独立计算的目标区间做
   对称差，分别报告**遗漏（missing_address）**与**额外（extra_address）**；
4. 翻转兄弟位检测**可合并兄弟（mergeable_sibling）**。

校验失败会作为 `verification_failure` 内部错误返回 HTTP 500，绝不会以 2xx 输出
一个未被证明正确的答案。失败原因逐条列出（见 `Violation.Category`）。

## 5. 三层独立参考（避免“自证”）

测试的参考答案**不来自被测核心自身**：

1. **位枚举真值（width ≤ 4）**：枚举该空间下**每一个**目标子集
   （width=3 全部 256 种，width=4 全部 65536 种），用最朴素的
   `floor(addr/2^e)*2^e == network` 逐地址判定成员资格；
2. **Trie 标注 oracle**：对完整二叉前缀树做后序标注（节点区间被某个目标区间
   完整包含→取该节点；完全不交→剪枝；部分相交→下降）。这是与生产贪心**不同的
   算法**，并在小位宽下与位枚举真值逐位比对通过；
3. **被测算法**：其输出必须与前两者一致，并通过第 4 节的结构校验。

此外还有 width=5 的“允许前缀 × 排除前缀”全配对（3969 组）、width 4..10 的随机
（含重复、相邻、重叠）差集测试，以及真实 IPv4/IPv6 与 IPv6 极值（`::/0`、
`::/128`、`ffff...ffff/128`）的具体字面值断言。

## 6. 复杂度

设归一化后区间数为 `r`、输出前缀数为 `k`：

- 集合运算：`O(n log n)`（排序主导，`n` 为输入前缀数）；
- 覆盖：输出每块时仅做常数次大整数位运算，`O(k)` 次 big.Int 操作；
- 空间：`O(n + k)`。

IPv6 的 `k` 最坏为 `O(w)`（单端挖洞产生长度 1..128 的链，共 128 块），与地址
总数 `2^128` 无关，故不会枚举地址。
