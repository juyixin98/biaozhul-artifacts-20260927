# 合并边界语义

本文档定义 merge3 的精确行为边界。术语:**基线**(base)是共同祖先,
**两侧**(local / remote)分别基于基线演化。行号均为从 0 开始的半开区间
`[start, end)`。

## 1. 文本规范(app.textnorm)

- 只把 `\n`、`\r\n`、`\r` 视为行结束符;`\x0b`、` ` 等 Unicode 行边界
  **不**作为分行点,避免静默重构文本。
- `split_lines` 保留每行的行结束符,且与 `join_lines` 严格互逆:
  合并输出是原始输入行片段的拼接,不存在隐式规范化。
- 每份文本有一个画像(`TextProfile`):行结束符风格
  (lf/crlf/cr/mixed/none)、是否以换行结尾、行数、SHA-256。

## 2. 区间编辑(app.edits)

- 编辑表示为 `Edit(start, end, replacement)`:把基线第 `[start, end)` 行
  替换为 `replacement`。`start == end` 为插入;`replacement` 为空为删除。
- 比较键规则:
  - 行内容相同即视为同一行,行结束符**口味**(`\n` vs `\r\n`)不参与比较。
    因此「只把 LF 改成 CRLF」不产生编辑、不会被合并进去,而是产生一条
    诊断说明(`... differs from base only in line-terminator flavor ...`)。
  - 例外:没有行结束符的最后一行,其比较键带 EOF 哨兵。这样
    「末尾无换行 → 有换行」会被识别为真实编辑;否则在末尾追加行时,
    未终止的末行会与新行粘连,造成静默改写。
- 差异算法为 `difflib.SequenceMatcher(autojunk=False)`,重复行场景下结果
  确定(最长匹配优先保留后缀)。

## 3. 冲突规则(app.merge)

两侧编辑按基线区间合并:

| 情形 | 结果 |
| --- | --- |
| 区间不相交(含边界相邻) | 自动合并,两侧都应用 |
| 完全相同的编辑(区间、内容、行结束符都相同) | 应用一次 |
| 同一位置插入不同内容 | 冲突 `same-point-insert`,不猜测先后顺序 |
| 一方删除的区间与另一方修改的区间相交 | 冲突 `delete-vs-modify` |
| 同一区间改成相同内容但行结束符不同 | 冲突 `line-ending-mismatch`,不替用户选择行结束符 |
| 其他区间相交(含传递闭包成组) | 冲突 `overlap` |

边界细则:

- 插入位于另一方编辑区间的**边界**(起点或终点)不算冲突;严格位于区间
  **内部**才算冲突。
- 同一基线位置既有插入又有替换时,**插入排在替换之前**。该规则与左右侧
  无关,是确定性的。
- 相交编辑按传递闭包聚成一个冲突组:若 A 与 B 相交、B 与 C 相交,则
  A、B、C 属于同一冲突。

## 4. 冲突块与重建

冲突输出为标记块(标记行的行结束符取基线的主导行结束符):

```
<<<<<<< local
<local 侧原始行>
||||||| base
<基线原始行>
=======
<remote 侧原始行>
>>>>>>> remote
```

- 结构化冲突对象携带**三方源范围**:基线、local、remote 各自的行号区间
  与原始行,合并结果本身不猜测用户意图。
- `resolve3` / `POST /merges/{id}/resolve` 按显式选择重建:每个冲突必须
  给出 `"local"` / `"base"` / `"remote"` 之一;缺项抛
  `unresolved-conflicts`,非法值抛 `unknown-choice`。重建输出逐字节取自
  所选侧的原始行。
- 仅冲突标记表示中:若某方小节的最后一行没有行结束符,为避免与后续标记
  行粘连,会补一个行结束符并记录诊断说明;显式重建不受此影响。

## 5. 行结束符与末尾换行

- 未编辑的行保留基线原样;被某侧编辑覆盖的行携带该侧的行结束符。
- 末尾换行状态不被静默改写:结果与基线的末尾换行状态不同时,诊断会记录
  是哪一侧的编辑导致(`trailing newline added/removed by <side> edit(s)`)。

## 6. 诊断与失败类别

- 每条诊断是带 `request_id` 的 JSON 行,记录关键状态(各侧哈希指纹、
  应用的编辑数、冲突类别、拒绝原因),说明为什么接受、拒绝或无法判定。
- 文本内容永不写入日志,只写 SHA-256 前 12 位与字符数。
- API 失败响应统一为 `{"error": {"category", "detail"}}`,类别:
  `merge-not-found`(404)、`version-not-found`(404)、
  `nothing-to-resolve`(409)、`unresolved-conflicts`(422)、
  `unknown-choice`(422)、`invalid-role`(422)。

## 7. 已知限制

- 行级粒度:同一行内的字符级并发修改会整行冲突。
- 移动被表示为「删除 + 插入」,不与另一方的删除/插入做移动感知匹配。
- SQLite 单写者:未做并发写入的负载验证(见 scripts/verify.py 的未执行清单)。
