# 输入语言

两种等价输入形式：**文本语法**（`"expr"` 字段）和 **JSON AST**（`"expr_json"` 字段）。
二者由 `src/lang` 模块处理，不依赖 BDD 内核；模块内的 `Expr::eval` 是
与求解内核无关的独立递归解释器，证据测试以它为真值预言机。

## 文本语法

优先级从低到高（同级左结合，除非注明）：

```text
expr    := iff
iff     := implies ("<->" implies)*        // 同或/双向蕴含，左结合
implies := xor     ("->"  xor)*            // 蕴含，左结合
xor     := or      ("^"   or)*             // 异或
or      := and     ("|" and)*              // 逻辑或，也接受关键字 or
and     := unary   ("&" unary)*            // 逻辑与，也接受关键字 and
unary   := "!" unary | "not" unary | atom  // 逻辑非
atom    := "true" | "false" | ident | "(" expr ")"
```

- 标识符：字母或下划线开头，后跟字母/数字/下划线。
- 关键字（`true false and or not`）不能作变量名。
- 空白（空格、制表符、换行）仅作分隔。

### 例子

| 文本 | 含义 |
|---|---|
| `a & b \| c` | `(a & b) \| c` |
| `a -> b ^ c` | `a -> (b xor c)`（xor 结合比 implies 紧） |
| `a -> b -> c` | `(a -> b) -> c`（左结合） |
| `not a or b` | `!a \| b` |
| `!(a <-> !b)` | 对同或取非 |

解析失败返回 422 `parse_failed`，错误体带字符位置（如 `parse error at 2: ...`）。

## JSON AST

`Expr` 的 serde 外部标签枚举：

| 变体 | JSON 形态 | 说明 |
|---|---|---|
| 常量 | `{"Const": true}` / `{"Const": false}` | |
| 变量 | `{"Var": "a"}` | 必须在管理器变量序中声明 |
| 非 | `{"Not": {...}}` | 一元 |
| 与 | `{"And": [ ... ]}` | n 元，空表 = `true` |
| 或 | `{"Or": [ ... ]}` | n 元，空表 = `false` |
| 异或 | `{"Xor": [ ... ]}` | n 元左结合 |
| 蕴含 | `{"Implies": [ {...}, {...} ]}` | 二元 `[a, b]` 表示 a→b |
| 同或 | `{"Iff": [ {...}, {...} ]}` | 二元 |

样例见 `samples/build_mux_ast.json`。

## 变量与变量序

- 管理器创建时一次性给出固定变量序，例如 `["a","b","c"]`；重复变量名被拒绝。
- 变量序索引即变量身份（`VarId`），非终节点严格按序分流，这是 ROBDD 规范性的前提。
- 表达式引用未声明变量返回 422 `unknown_variable`。

## 等价查询里的身份映射

`POST /v1/equivalence` 面对的两个表达式可以使用不同变量名。
`mapping` 是 `左名 -> 右名` 的映射：

- 同名变量自动视为恒等对（可省略）；
- 映射必须是双射，否则返回 422 `mapping_rejected`（左/右重名或多对一）；
- 两边出现的所有变量都必须被身份覆盖，否则同样拒绝（而不是猜测等价）。

例：`{"x":"p","y":"q","z":"r"}` 使 `x & y -> z` 与 `p & q -> r` 判为同一函数。
